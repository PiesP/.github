# Support

Search the target repository's README, support policy, and existing issues
before opening a report. Use its local issue template when present. Include the
project version, supported environment, reproduction steps, and expected and
observed behavior. Share a minimal nonprivate fixture when it helps reproduce
the problem.

For translation reports, identify the supported game build, affected term, and
suggested wording. For Windows file operations, preserve recovery data and use
the repository's documented recovery path. For browser projects, report the
browser version and relevant conversion, extension, or host-site behavior.

Security reports follow the target repository's SECURITY.md. Do not publish
credentials, private files, or exploit details in an ordinary issue.
